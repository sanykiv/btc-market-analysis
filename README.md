# BTC Market Analysis — методология проверки гипотез на крипто-данных

Проект не про поиск «грааля», а про **дисциплину проверки торговых гипотез**: как отличить
реальный сигнал от артефакта на финансовых данных. Главная ценность — раздел **«Ревизия»**,
где выводы первой, наивной части проекта намеренно пересматриваются строгими методами.

## TL;DR — что показывает проект

Проверены 3 классические гипотезы на BTC/USDT, сначала «в лоб», затем со строгой ревизией.
**Итог важнее самих гипотез: из трёх находок строгую проверку переживает только одна.**

| Гипотеза | Наивный вывод | После ревизии |
|---|---|---|
| Отскок от поддержки | «работает», p≈0 | **мираж** — это дрейф рынка, edge ≈ 0 (p≈0.6) |
| Сезонность (дни/месяцы) | пн / ср / октябрь значимы | после Bonferroni выживает **только октябрь** |
| Объём при пробоях | работает, p=0.005 | **подтвердилось**, устойчиво; фильтр режет ложные пробои 33% → 12% |

**Методический урок:** на трендовом активе доходность нельзя тестировать против нуля
(сравнивай с рынком), нельзя доверять p-value на перекрывающихся выборках, при множестве
проверок нужна поправка на множественность, а любой положительный результат сначала
пытаешься опровергнуть.

## Данные

- BTC/USDT, дневные свечи, источник — Binance через `ccxt`.
- Период: 2017-08 — 2026, ~3234 свечи. Очистка, проверка качества, расчёт индикаторов.

## Что внутри

1. **EDA и индикаторы** — RSI(14), SMA 20/50/200, уровни поддержки/сопротивления (`scipy.argrelextrema`).
2. **Бэктесты 3 гипотез** с t-тестами (наивная версия).
3. **🔍 Ревизия** — повторная строгая проверка:
   - тест против **дрейфа рынка**, а не против нуля;
   - устранение **двойного счёта** перекрывающихся наблюдений;
   - поправка **Bonferroni** на множественную проверку (19 гипотез сезонности);
   - непараметрический тест **Манна–Уитни** для устойчивости при малых выборках.

## Известные ограничения (честно)

- **Look-ahead bias в уровнях.** `argrelextrema(order=10)` подтверждает экстремум по 10
  *будущим* барам, поэтому уровень «известен» задним числом. Уровни здесь корректно трактовать
  как **риск-инструмент (постановка стопа)**, а не как сигнал входа в реальном времени.
- **Без транзакционных издержек.** Комиссии и проскальзывание в доходностях не учтены.
- **Сезонность по дням оценена дневным t-тестом** — он не учитывает автокорреляцию внутри
  месяца; вывод по октябрю стоит перепроверить агрегацией по годам / block-bootstrap.

## Что уже сделано из «следующих шагов»

- ✅ **Аудит объёмного сигнала на look-ahead** (раздел «Ревизия 4»): результат устойчив —
  по построению уровня через `argrelextrema(order=k)` пробой внутри окна подтверждения
  невозможен, поэтому честная задержка признания уровня не меняет вывод.
- ✅ **Перенос метода на DEX / on-chain данные** (раздел «Перенос на DEX»): тот же конвейер
  запущен на пуле WETH/USDC Uniswap v3 через публичный API GeckoTerminal. Метод переносится,
  но доступной дневной истории пула (~6 мес) мало для статвыводов — тот же урок про размер
  выборки, что и «2 года vs 9 лет».
